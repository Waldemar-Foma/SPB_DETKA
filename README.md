# 🏭 Автоматический парсер реестра Минпромторга (ГИСП)

Модуль фонового обогащения данных для автоматического извлечения актуального перечня производителей из Государственной информационной системы промышленности (ГИСП). Разработан командой **AXL** для обеспечения системы АИС ГЗ свежими и достоверными данными о контрагентах.

Скрипт решает главную проблему государственных порталов — жесткую Anti-Bot защиту (Qrator WAF). Вместо обычных `GET`-запросов, модуль использует невидимый браузер, который имитирует действия человека, проходит проверки безопасности, забирает сессионные куки и скачивает тяжеловесный Excel-файл.

---

## 🚀 Ключевые особенности

* **Умный обход WAF (Qrator):** Использует `async_playwright` (Headless Chromium) с подменой User-Agent для легитимного входа на портал.
* **Полная асинхронность:** Написан на `asyncio`. Скрипт не блокирует основной поток выполнения и не конфликтует с внутренними процессами (решена проблема `Event loop is already running`).
* **Фоновый демон (Worker):** Работает в режиме `while True`, самостоятельно засыпая и просыпаясь ровно через 24 часа для поддержания актуальности базы.
* **Готовность к интеграции:** Скачанный бинарный `.xlsx` файл "на лету" конвертируется в `pandas.DataFrame` для быстрой выгрузки в векторную БД или SQL.

---

## 🛠 Требования и установка

Для работы парсера потребуется Python 3.8+ и установленные системные зависимости для работы виртуального браузера.

**1. Установите необходимые Python-библиотеки:**

```bash
pip install pandas playwright openpyxl

```

**2. Инициализируйте ядро Playwright (скачивание Chromium):**

```bash
playwright install chromium

```

---

## 💻 Использование

Запустите скрипт через терминал:

```bash
python3 parser.py

```

**Как выглядит жизненный цикл работы скрипта:**

1. Запускается невидимый Chromium.
2. Происходит переход на главную страницу каталога ГИСП (`/pub/prod/`) для прохождения JS-челленджа от Qrator и генерации кук.
3. Ожидание 3 секунды для надежной фиксации сессии.
4. Отправка прямого запроса на скачивание актуального файла реестра (`production_res_valid_only.xlsx`). Специфическая ошибка Playwright `Download is starting` безопасно перехватывается и игнорируется.
5. Файл сохраняется локально как `registry.xlsx` (размер ~60+ МБ).
6. Файл считывается через `pandas`, выводится количество актуальных производителей.
7. Программа уходит в спящий режим на 86400 секунд (24 часа).

## ⚙️ Интеграция в архитектуру платформы

Текущая версия скрипта выводит данные в терминал. Чтобы подключить парсер к основной базе платформы, найдите строку `df = pd.read_excel("registry.xlsx")` в файле `parser.py` и добавьте логику сохранения.

**Пример выгрузки в базу PostgreSQL (через SQLAlchemy):**

```python
from sqlalchemy import create_engine

# ... код загрузки df ...
df = pd.read_excel("registry.xlsx")

# Очистка и фильтрация нужных колонок (ИНН, Название)
df_filtered = df[['ИНН', 'Наименование предприятия']]

# Подключение к БД и загрузка
engine = create_engine('postgresql://user:password@localhost:5432/ais_db')
df_filtered.to_sql('minpromtorg_registry', engine, if_exists='replace', index=False)
print("База данных платформы успешно обновлена!")

```

## ⚠️ Возможные проблемы (Troubleshooting)

* **Ошибка `ValueError: Excel file format cannot be determined`:**
Возникает, если сервер всё-таки заблокировал запрос и вместо таблицы отдал HTML-страницу с ошибкой 403. Убедитесь, что шаг перехода на главную страницу (генерация токенов) отрабатывает корректно и таймаут ожидания `asyncio.sleep(3)` не слишком мал для вашего интернет-соединения.
* **Ошибка `TimeoutError` при скачивании:**
Сервер Минпромторга может быть перегружен. В скрипте установлен `timeout=120000` (2 минуты). Если скачивание занимает больше времени, увеличьте этот параметр.

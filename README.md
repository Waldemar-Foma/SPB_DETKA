# Сервис подбора исполнителей

Веб-сервис для заказчика: создать заявку → описать потребность или загрузить ТЗ → получить TOP-5 подходящих контрагентов → сравнить их на карте/в списке → выбрать исполнителя → получить контакты → завершить заказ → оставить отзыв.

Проект работает локально через Docker и при необходимости публикуется в интернет через Caddy.

---

## 1. Основной сценарий

После входа заказчик попадает в **«Мои заявки»**.

Дальше:

1. Нажимает **«Создать заявку»**.
2. Выбирает один из вариантов:
   - загрузить ТЗ;
   - описать заказ вручную.
3. Система анализирует заявку и формирует TOP-5 компаний.
4. Кандидатов можно смотреть:
   - на карте;
   - списком;
   - с фильтрацией по типу компании.
5. Для каждого кандидата показываются:
   - совпадение с запросом;
   - опыт в категории;
   - win rate;
   - отзывы;
   - логистика;
   - текущая нагрузка внутри сервиса;
   - подробное объяснение, почему компания попала в рекомендации.
6. Заказчик выбирает исполнителя и получает контактные данные.
7. **До завершения заказа исполнителя можно изменить**: в карточке заявки есть кнопка **«Изменить исполнителя»**, которая снова открывает карту и TOP-5.
8. После нажатия **«Заказ завершён»** вернуться к подбору и изменить исполнителя уже нельзя.
9. После завершения заказа можно оставить отзыв 1–5.

## 2. Как работает подбор

Подбор состоит из нескольких слоёв.

### Первичный поиск

Используется:

- `all-minilm`;
- FAISS.

Текст заявки превращается в embedding, после чего FAISS быстро формирует семантически подходящий пул кандидатов.

### Финальное ранжирование

Дальше backend учитывает:

- смысловое совпадение;
- ОКПД2;
- историю релевантных закупок;
- количество участий и побед;
- win rate;
- географию и логистический смысл;
- отзывы пользователей;
- текущую нагрузку компании внутри сервиса;
- дополнительный semantic score от `multilingual-e5-base`.

После этого формируется итоговый TOP-5.

### Qwen

`qwen2.5:3b` не выбирает победителя. Она получает уже рассчитанные факты и пишет понятное объяснение для заказчика. Карточка компании больше не ждёт генерацию: метрики, отзывы, логистика и остальные данные отображаются сразу, а блок Qwen догружается отдельно и появляется после готовности ответа.

В объяснение передаются:

- предмет заявки;
- специализация компании;
- релевантные примеры прошлых работ;
- статистика участий и побед;
- win rate;
- отзывы;
- логистика;
- нагрузка;
- опыт работы с этим заказчиком, если он есть.

Для разных компаний используются разные структуры текста, поэтому объяснения не должны выглядеть как одна и та же заготовка.

Если Qwen недоступна, сервис использует rule-based fallback и продолжает работать.

## 3. Что нужно для запуска

На Windows нужен **Docker Desktop**.

Python, Flask, Ollama, FAISS, Playwright и остальные зависимости вручную устанавливать не нужно — они находятся внутри Docker-контуров проекта.

Для первого запуска нужен интернет, потому что Docker может скачать:

- Python image;
- Ollama;
- `qwen2.5:3b`;
- `all-minilm`;
- llama.cpp server;
- E5-модель, если её ещё нет локально.

Первый импорт реального датасета также может занять несколько минут.

# 4. Локальный запуск

Запустите Docker Desktop и дождитесь готовности Docker Engine.

Затем дважды нажмите:

```text
START_LOCAL.bat
```

Старый `START.bat` оставлен как совместимый алиас и тоже запускает локальный режим.

После запуска сайт откроется по адресу:

```text
http://127.0.0.1:5000
```

Страница входа:

```text
http://127.0.0.1:5000/auth/login
```

# 5. Запуск в интернет через Caddy

Для публикации используется тот же домен и схема, что и в предыдущем проекте:

```text
https://neva-hub.space:18443
```

Запуск:

```text
START_INTERNET.bat
```

Этот режим поднимает те же контейнеры приложения и дополнительно запускает Caddy.

Caddy:

- принимает HTTPS;
- автоматически управляет TLS-сертификатом;
- проксирует запросы во Flask-контейнер `app:5000`;
- наружу публикуется порт `18443`.

Используемая схема Docker:

```text
Internet
   ↓
https://neva-hub.space:18443
   ↓
Caddy :443
   ↓
app:5000
```

Для той же сетевой схемы на роутере/сервере должны оставаться пробросы:

```text
TCP 18443 → этот компьютер:18443
TCP 80    → этот компьютер:80
```

Порт 80 нужен Caddy для автоматического получения/обновления сертификата через HTTP challenge.

DNS `neva-hub.space` должен указывать на ваш внешний IP.

Конфигурация находится в:

```text
Caddyfile
docker-compose.internet.yml
```

## 6. Реальный датасет

Если рядом с папкой проекта лежит архив вида:

```text
RLT.Uni_*.zip
```

launcher автоматически копирует его в:

```text
datasets/source.zip
```

и при первом запуске строит REAL-базу.

Пример структуры:

```text
hackathon/
├── RLT.Uni_СПБ_1-2_10_2026.zip
└── procurement_ready_v19/
    ├── START_LOCAL.bat
    └── START_INTERNET.bat
```

Можно также передать путь к архиву вручную:

```bat
START_LOCAL.bat "C:\path\to\dataset.zip"
```

или:

```bat
START_INTERNET.bat "C:\path\to\dataset.zip"
```

После успешного импорта создаётся:

```text
instance/REAL_DATA_READY
```

Следующие запуски используют уже готовую SQLite-базу.

## 7. Админ-панель

Администратор:

```text
admin@local.test
Admin2026!
```

Админ-панель:

```text
/admin/
```

В ней можно:

- посмотреть режим базы REAL/DEMO;
- проверить количество контрагентов, заявок и исторических побед;
- проверить FAISS + all-minilm;
- проверить Qwen реальным inference-запросом;
- запустить синхронизацию ГИСП;
- повторно применить уже скачанный `registry.xlsx`;
- посмотреть журнал работы ГИСП;
- запустить обогащение тестовыми данными с Yandex Disk;
- при наличии `DADATA_TOKEN` дополнить реальные компании названием, ОГРН, ОКВЭД, адресом и регионом через DaData.

Кнопки админ-панели инициализируются frontend-модулем `adminPage.js` и обращаются к `/admin/api/...`.

## 8. ГИСП

В админ-панели есть две операции:

### Скачать и синхронизировать

Запускает синхронизацию реестра в фоне. Сначала система пытается получить официальную XLSX-выгрузку с `portfolio.gisp.gov.ru` / `gisp.gov.ru`. Если ГИСП возвращает HTTP 403 для автоматического клиента, процесс больше не висит на многоминутных download-timeout: он быстро переключается на публичное независимое зеркало `tovarminpro.online` и проверяет ИНН компаний из FAISS-пула. Такая fallback-выгрузка помечается как частичная и только добавляет подтверждённых производителей, не сбрасывая ранее подтверждённые данные официальной полной выгрузки. Результаты запросов к зеркалу кэшируются в `data/gisp_mirror_cache.json`. Старый `registry.xlsx` не затирается, пока новая выгрузка не прошла проверку.

### Применить текущий XLSX

Если `data/registry.xlsx` уже есть, можно не скачивать его заново, а сразу обогатить локальную БД.

## 9. Тестовые данные + DaData

В проект встроен дополнительный контур обогащения. Он запускается из админ-панели кнопкой **«Синхронизировать данные»**.

Источник тестовых данных по умолчанию:

```text
https://disk.yandex.ru/d/CI8l7NXJ_k7HYA/Тестовые данные_1140
```

Система:

1. скачивает тестовые извещения и ТРУ в `data/test_enrichment/`;
2. связывает их по `lot_id` с победителями из исходного `Поставщики_24-25.csv`;
3. дополняет `specialization`, ОКПД2 и исторические победы прямо в основной таблице компаний;
4. не дублирует уже существующие исторические записи при повторном запуске;
5. использует обновлённый профиль в финальном ранжировании и объяснениях Qwen.

DaData подключается без отдельной Python-библиотеки через HTTP API. Токен не хранится в исходниках. Скопируйте `.env.example` как `.env` и задайте:

```text
DADATA_TOKEN=ваш_токен
```

Если токен не задан, синхронизация тестовых данных всё равно выполняется, а DaData просто пропускается. Ответы DaData кэшируются в `data/dadata_cache.json`, поэтому повторный запуск не расходует лимит повторно.

## 10. Проверка проекта

Когда Docker-контейнеры уже запущены, можно выполнить:

```text
CHECK_PROJECT.bat
```

Он запускает проверки Python/pytest и синтаксиса JavaScript.

Для просмотра контейнеров:

```bat
docker compose ps
```

Логи приложения:

```bat
docker compose logs -f app
```

Для интернет-режима логи Caddy:

```bat
docker compose -f docker-compose.yml -f docker-compose.e5.yml -f docker-compose.internet.yml logs -f caddy
```

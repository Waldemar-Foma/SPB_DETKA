# СПб Контрагенты

Интеллектуальный сервис поиска, обогащения и оценки релевантности
исполнителей государственных закупок. Демонстрационный проект для хакатона.

## Возможности

- Распознавание закупки по текстовому запросу (название, ОКПД2, номер).
- Взвешенный скоринг контрагентов по пяти факторам.
- Ранжированная лента с быстрыми фильтрами и сортировкой.
- Детальный профиль контрагента в боковой панели:
  - разбивка оценки по факторам (radial + progress bars);
  - контактная информация и мини-карта;
  - гистограмма контрактов по годам;
  - быстрые действия и экспорт карточки.
- Светлая и тёмная темы, автоматическое определение системной темы.

## Стек

| Слой | Технологии |
|------|-----------|
| Backend | Python 3.11, Flask 3, SQLAlchemy 2, SQLite / PostgreSQL |
| Frontend | Jinja2, Vanilla JS (ES-модули), чистый CSS (design tokens) |
| Иконки | Tabler Icons (SVG-спрайт) |
| Графики | Chart.js, Leaflet |
| Тесты | pytest |

## Архитектура

```
Запрос → Blueprint → Service → Model → SQLAlchemy
             ↑
            JSON
             ↓
       JS api/ → component/ → DOM
```

- **Blueprints** — только HTTP-слой: парсинг запроса, вызов сервиса, `jsonify`.
- **Services** — бизнес-логика (скоринг, матчинг, фильтрация) в виде чистых функций.
- **Models** — персистентность и сериализация (`to_dict()`, `to_card()`, `to_details()`).
- **JS `api/`** — единственная точка сетевых вызовов (`fetch`).
- **JS `components/`** — по одной функции на компонент, возвращают DOM-узлы.
- **CSS** — `tokens → base → layout → components → pages → themes`.
  Все цвета, отступы, радиусы — через CSS-переменные.

```

├── config.py             # конфиги dev/prod/test

├── backend/
```

## Установка и запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python seed.py
python app.py
```

Приложение доступно на `http://localhost:5000`.

## API

| Метод | Endpoint | Назначение |
|-------|----------|-----------|
| POST | `/api/v1/procurement/analyze` | Распознать закупку по запросу |
| GET  | `/api/v1/procurement/<number>/suppliers` | Ранжированный список контрагентов |
| GET  | `/api/v1/suppliers/<inn>/details` | Детальный профиль контрагента |

Параметры списка: `sort`, `company_type`, `region`, `min_experience`, `min_revenue`, `q`.

## Модель скоринга

Итоговый балл — взвешенная сумма пяти субиндексов:

| Фактор | Вес |
|--------|-----|
| Совпадение ОКПД2 | 0.30 |
| Семантическое совпадение продукции | 0.25 |
| Опыт аналогичных контрактов | 0.20 |
| Региональное соответствие | 0.15 |
| Масштаб компании | 0.10 |

Интерпретация: ≥90 — высокая, 70–89 — хорошая, 50–69 — средняя, <50 — низкая.

## Дизайн-система

- **Типографика:** Inter, размеры от 11 до 24 px.
- **Цвета:** централизованы в `static/css/themes/{light,dark}.css`.
- **Токены:** отступы, радиусы, тени — в `static/css/tokens.css`.
- **Иконки:** Tabler Icons, толщина линии управляется `--icon-stroke`.

## Соглашения

- 1 файл — 1 ответственность (модель / сервис / blueprint / компонент).
- Вся бизнес-логика — в `services/`, HTTP-роуты остаются тонкими.
- Фронтенд не работает с `fetch` напрямую — только через `js/api/`.
- Никаких сторонних CSS-фреймворков — только собственные токены и компоненты.
- Никаких эмодзи в интерфейсе — только SVG-иконки.
